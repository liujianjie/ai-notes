## 出发点

> 现在开源模型这么火热，Kimi K3 等，这样的话 Claude Code、OpenAI 还有什么优势？有开源模型是不是人人都可以自己部署一个属于自己的模型？
>
> （追问）现在很多都看好开源模型，是否会威胁到 Claude Code、OpenAI 等？

## 一句话结论

**开源打掉的是闭源的定价权和估值倍数，不是它的收入和地位。护城河没消失，但它从「模型权重」搬到了「agent harness + 数据飞轮 + 责任承担」这三处——而 harness 这一层正在被开源追赶，这是整个判断里最脆弱的地方。至于人人自部署：不能，且门槛在变高不是变低。**

## 一、事实基线：K3 是什么

| 项目 | 数值 |
|---|---|
| 发布 | 2026-07-16，WAIC 大会 |
| 参数 | **2.8 万亿**（MoE，896 专家，每次激活 16 个） |
| 上下文 | **1 亿 token** |
| 权重释放 | 2026-07-27 完全开放 |
| 历史坐标 | DeepSeek 6700 亿 → 智谱 GLM-5.2 → K3 2.8 万亿，半年涨 4 倍以上 |

K3 这件事同时证明了两件相反的事：**开源在能力上追平了**，以及**你跑不动它**。后半句是第二问的全部答案。

## 二、数据修正留痕（重要）

本篇第一版判断建立在一个过期数据上，此处留痕：

| 曾引用 | 实际状态 |
|---|---|
| 「开源占企业 AI workload 13%，半年前是 19%，份额在跌」 | 出自 **Menlo Ventures 2025 年中**报告（对 150 位技术负责人的调研）。**2026 年的更新版查不到**，该数字当前的真实状态是**未知**，不能用来证明任何方向 |
| 同源的「闭源占部署负载 87%」（2.6 亦引用） | 同一份调研的另一面，时点问题一致。LLM.co 在 2026-03 仍在转引，但未见独立重采 |

**教训（方法论）**：AI 领域的份额类调研数据 **半年即过期**。2025 年中那个时点，正好落在 DeepSeek-V3/R1 与 Kimi K2 系列爆发**之前**，用它论证 2026 年的开源趋势方向可能整个反了。**引用任何份额/占比数据前先核对采样时点。**

## 三、K3 到底赢了没有：赢耐力，输纵深

| 基准 | K3 | 最强闭源 | 判读 |
|---|---|---|---|
| Terminal-Bench 2.1 | **88.3**（自报，KimiCode harness） | Fable 5 = 84.6 | Artificial Analysis 独立验证只有 **85** |
| SWE Marathon（最长程） | **40.0** | Opus 4.8 = 40.0 / GPT-5.6 = 39.0 / Fable 5 = 35.0 | K3 确实领先 |
| Program Bench | **77.8** | GPT-5.6 Sol = 77.6 | 领先 0.2 分，噪音级 |
| **DeepSWE（深度仓库理解）** | 67.5 | GPT-5.6 Sol = **73.0** / Fable 5 = 70.0 | **开源明显落后 5.5 分** |

### 这张表最重要的是它的脚注

**Claude Opus 4.8 在 Anthropic 自家 scaffold 上 SWE-bench 得 69.2%，在 Scale AI 标准化 SEAL 榜上只有 51.9%——同一个模型，换 harness 差 17.3 分。** 而 K3 的成绩单本身就混用了三套 harness（KimiCode / Claude Code / mini-SWE-agent）。

> **方法论结论：所有跨模型的 agent 榜单，在 harness 不统一时基本不可读。** 看到"某开源模型超越 Claude"的标题，第一件事是查它用的什么 scaffold，第二件事是查有没有独立第三方复现。

## 四、护城河搬到了哪里

权重免费 ≠ 能力免费。闭源真正的壁垒已不在模型层：

| 位置 | 具体是什么 | 开源为什么补不上 | 稳固度 |
|---|---|---|---|
| **Agent harness / 产品工程** | 上下文管理、工具编排、权限模型、错误恢复、子 agent 调度 | 17.3 分的实证价值 | ⚠️ **正在被追** |
| **RL 环境与数据飞轮** | 真实用户 agent 轨迹（哪步改对、哪次回滚）= 训练信号 | 开源发权重不发飞轮 | ✅ 稳 |
| **推理基础设施规模效应** | 大 batch、continuous batching、跨用户 prefix cache 共享 | 这是单位 token 成本的来源；自建是 batch=1、cache 不共享、夜间空转 | ✅ 稳 |
| **责任承担** | 侵权赔付、SOC2、审计链路、出事有人签字 | 权重是 MIT 协议，出事没人负责 | ✅ 稳 |

### 但 harness 这一层的判断要反过来

初版认为「harness 是护城河」。17.3 分坐实了它值钱，却同时暴露一个结构性问题：

> **harness 值 17 分，恰恰说明它是可分离、可复制、可迁移的一层。开源 harness 能套任何模型，Anthropic 的 harness 只能套自己的模型。**

更要命的是**品类定义的外溢**：Claude Code 自己把产品形态教给了市场。定义一个新品类的成本远高于抄一个已被验证的品类——OpenCode、Cline、Kimi CLI 不必再回答"terminal agent 该长什么样"，那道题 Anthropic 已免费替它们做完。

### 开源 harness 生态的真实成熟度（初版严重低估）

| 工具 | 状态 |
|---|---|
| **Cline** | 61,000+ GitHub stars、**800 万+ 活跃开发者**；VS Code/JetBrains/Cursor/Windsurf/Zed/Neovim 全覆盖，已出 CLI |
| **OpenCode** | 被评为 Claude Code **最好的零成本 drop-in 替代**，模型支持面最广 |
| **OpenHands** | 长程自主任务（无人监督）方向最强 |
| **Kimi CLI** | Moonshot 官方，支持 **100 agent 并行 swarm** |
| **Qwen Code** | 阿里，Gemini CLI 的开源续命分支 |
| **Warp 2.0** | 2026-04 客户端开源（AGPL-3.0） |

## 五、威胁的真正路径：不是迁移，是定价锚

多数人把"开源威胁闭源"理解成"用户会迁移走"。真实机制更隐蔽：

> **用户只需要「有能力威胁迁移」，就足以打掉闭源的定价权。被侵蚀的首先不是收入，是毛利率和估值倍数。**

这解释了为什么"Anthropic 收入暴涨"**不构成**"没被威胁"的证据——涨的是量，压的是价。

## 六、反方证据：财务数据极硬

| 指标 | 数值 |
|---|---|
| Anthropic ARR 轨迹 | 2024-01 $87M → 2024-12 $1B → **2025 年底 $9B** → 2026-02 $14B → 03 月 $19B → 04 月 $30B → **05 月 $47B** |
| 日均新增年化收入 | 约 **$9,600 万** |
| 2026 全年 ARR 预期 | $75B–90B |
| **Claude Code 单品** | 超 **$2.5B** 年化 |
| 对比 OpenAI | ~$25B ARR，Anthropic 已反超 |
| 每 MAU 年收入 | Anthropic **$192** vs OpenAI **$23**（8 倍） |
| 估值 | Anthropic $9,650 亿 > OpenAI $8,520 亿（2026-05） |

**这发生在 DeepSeek、K2/K2.5、GLM、Qwen 全面开源之后。如果开源真在替代，这条曲线不可能长这样。**

**解释**：两件事可以同时为真——**蛋糕在暴涨**。开源抢份额，闭源吃增量，两边收入都涨。**份额之争的结果，要到蛋糕增速放缓才会显形。** 这是本篇最关键的一层推理，也是判断拐点的钥匙（见证伪信号第 1 条）。

## 七、分层失守顺序

不该问"Claude Code 会不会死"，该问"哪一层先失守"：

| 层级 | 状态 | 判断 |
|---|---|---|
| 批量低价值 token（分类/抽取/翻译/摘要） | **已失守** | 开源赢定了，闭源不该恋战 |
| 中价值编码（补全、单文件重构） | **正在失守** | Qwen-Coder + Cline 已够用 |
| 长程 agent（跨仓库、多小时、生产环境改动） | **未失守** | DeepSWE 落后 5.5 分就是这条防线 |
| 企业合规 / 责任承担 / 侵权赔付 | **短期不会失守** | 权重是 MIT，出事没人签字 |

## 八、概率分档（往后 24 个月，至 2028 年中）

**以下为主观赔率，不是数据。** 括号内是相对初版的调整。

| 剧本 | 概率 | 内容 | 触发条件 |
|---|:-:|---|---|
| **A. 量增价减** | **45%**（↓10） | 闭源收入继续涨，单价持续下行，估值倍数从"软件"向"基础设施"收敛 | 蛋糕继续扩张 + 开源持续施加价格锚定 |
| **B. harness 被追平，闭源退守高端** | **35%**（↑5） | 开源 harness + K3 级模型在 80% 场景够用，闭源被压回长程 agent 与合规 | 出现一个稳定跑赢 SEAL 标准榜的开源 harness |
| **C. 闭源重新拉开代差** | **15%** | 下一代 RL scaling / 长程能力出现开源追不上的断层 | DeepSWE 类纵深指标差距扩大而非收窄 |
| **D. 闭源彻底商品化** | **5%** | 只剩品牌和合规，毛利跌到云厂水平 | 推理成本再降一个数量级 + 大厂免费补贴 |

**下调 A、上调 B 的理由**：初版低估了开源 harness 生态的成熟度（Cline 800 万开发者、OpenCode drop-in、Warp 开源），且初版用于支撑 A 的核心数据（开源份额 13% 且在跌）已确认过期。

## 九、证伪信号（按信息量排序）

1. **蛋糕增速拐点 —— 唯一能同时判定 A/B 的指标。** Anthropic 日增 $9,600 万年化一旦掉到 $3,000 万以下，份额之争立刻显形
2. **Claude Code 的 $2.5B ARR 环比增速转负** → B 档上调到 50%+
3. **开源 harness 在统一标准榜**（SEAL 这类，不是自家 scaffold）**上跑赢闭源 scaffold** → B 档兑现
4. **DeepSWE 类深度指标被开源追平** → 最后一条技术防线失守，D 档从 5% 起跳
5. 反向信号：闭源在编码份额（Claude 曾达 54%）跌破 40% → 说明失守比预期快

## 十、第二问：人人自部署？不能

**「开源」在 2.8 万亿参数的尺度上，意思是「你可以看，但你跑不动」。**

### K3 的真实门槛

| 项目 | 数值 |
|---|---|
| 官方建议 | **64 卡以上超节点** |
| 权重体积（MXFP4 量化后） | 约 **1.4TB** |
| 实际显存需求（含激活 + KV cache） | **超 2TB** |
| 系统内存 | 每台服务器 512GB–1TB |
| 业内估算硬件成本 | 约 10 张 GB300，接近 **百万美元** |
| 月电费 | 上万美元 |

### 分层看你实际能得到什么

| 层级 | 硬件 | 实际能力 | 个人可行性 |
|---|---|---|---|
| 旗舰（K3 2.8T） | 64 卡+，~$1M | 榜单第一那个 | ❌ 不可能 |
| 中高（70B INT4） | 双 3090 48GB，8–12 tok/s | 能用，慢，功耗 700W+ | ⚠️ 发烧友 |
| 主力（32B 全精度） | 单 5090 32GB，35–50 tok/s | **约 GPT-4o-mini 水平** | ✅ 可行 |

**核心认知：你能部署的模型 ≠ 你看到的那个模型。** 新闻刷屏的是最强的那个，你家里跑的是缩水四五档的那个，中间差距不是量化能弥补的。而且**低精度量化对大模型的伤害远大于对小模型**——宁可跑小模型高量化，别跑大模型低量化。

参考数据：50 道 LeetCode 中等难度，Qwen3.5-72B Q4 通过率 42%，32B 为 31%；日常问答/写作/翻译两者差距已在 5–10% 内。

### 经济账（反直觉）

**个人自部署几乎永远算不过 API。** API 单价便宜正是因为集中式推理把硬件效率拉满（大 batch + 跨用户 prefix cache 共享），你自己跑就是把这份效率丢掉。

- **企业算得过**：日均 10 万次交互，年 API 成本 30–80 万元；本地一次性投入 50–200 万，5 年总成本可降 60–80%
- **个人算不过**：本地部署的价值不是省钱，是 **数据不出门 + 不被断供 + 无速率限制**

### 按诉求选

| 你要的是 | 结论 |
|---|---|
| 隐私 / 离线 | 32B 量化，值得做 |
| 省钱 | 用 API，本地更贵 |
| 最强能力 | 只能用云端，本地无解 |

## 十一、中国市场是另一道题

**Claude/OpenAI 在中国大陆无法合规商用——这不是技术问题。**

所以"开源会不会威胁 Claude Code"在中国语境下**问错了**。中国的真问题是：

> **K3/Qwen/GLM 开源自部署 vs 豆包/通义/文心的闭源 API**——一道纯粹的成本与可控性权衡，没有"闭源能力代差"这个变量。

这个区分对投资很关键：本仓库标的绝大多数在中国，中美两边的竞争结构不能混着推。参见 [2.3 中美AI叙事怎么读与投资推理的三处断裂](<./2.3 中美AI叙事怎么读与投资推理的三处断裂.md>)。

## 十二、投资含义：接回 2.6

### 1. 自部署门槛验证了 2.6 的情景 C 低概率

64 卡超节点不是"企业买几张卡"能解决的。**门槛随代际在拉高不是收敛**，支持 2.6 给自建情景仅 20% 的判断。

### 2. K3 强化而非削弱 HBM 逻辑

**2.8 万亿参数 + 1 亿 token 上下文 → KV cache 显存需求爆炸性上升。开源模型越强，单次部署吃的 HBM 越多。**

### 3. 剧本 B 对硬件链反而是利好

| 结果 | 对硬件链的影响 |
|---|---|
| 谁赢，token 总量都涨 | 硬件逻辑**完全不受影响** |
| 剧本 B 兑现（开源 harness 追平）→ 部署更分散 | 按 2.6 的二阶效应（**分散部署比集中部署更费卡**），HBM 逻辑**增强** |
| 真正受损的 | 只有闭源模型公司的**估值倍数**，不是收入，更不是硬件链 |

### 4. 需要修正 2.6 的一处表述

> 2.6 原文：「模型层 / API 生意 —— 唯一确定的输家」

**精确表述应为：输的是纯卖 token 的毛利率和估值倍数；卖 agent 产品的收入端目前还在赢。** 证据是 Claude Code 单品 $2.5B 年化、Anthropic 五个月五倍。这一行在 2.6 里已加注修正。

## 结论的可打脸之处

**最脆弱的一环是「harness 是护城河」。** 如果 12 个月内出现一个开源 harness 在统一标准榜上稳定跑赢闭源自家 scaffold，本篇 A 档 45% 应立刻下调至 30% 以下、B 档上调至 50%+，第四节那张表的第一行要整行划掉。

**第二脆弱的是拿 Anthropic 财务当"没被威胁"的证据。** 那条曲线只证明蛋糕在涨，不证明份额守住了。这两件事在数据上暂时无法分离——这是本篇论证的真实边界。

以上概率为主观赔率，用于研究判断，不构成买卖指令。新证据出现后需回来更新赔率并注明改了哪档、为什么。
