# 文档命名与归档规范(适用本仓库所有 md)

## 一律用 `N.M 标题.md` 编号
- `N` 是主题模块,`M` 是模块内顺序。**同一模块的文档共用一个 N,序号必须挨在一起。**
- 新主题开新的一级序号(下一个整数 N),不要挂到已有模块下当子号。
- `0.x` 留给原始 prompt / 提示词记录。
- 带强时点属性的(具体价格、概率赔率、当期财报)在序号后加日期:`3.1 2026-07-25 标题.md`。纯认知/方法类不加日期。
- 一级序号大致按建档时间排,但**模块归属优先于时间**:后写的续篇仍挂回原模块。例:`2.3` 比 `3.1` 晚建档,因为它是 `2.1` 的方法篇,仍归 2.x。

## 目录归属
- `AIStocking/` —— 投资标的、板块、择时判断
- `AIKnowlege/` —— 方法论、产业认知、叙事拆解
- `AIStockAnalayDocs/` —— 单公司深度、策略草稿
- 仓库根 —— 与投资无关的工程/工具/生活类笔记

## 已有阅读顺序的目录不要重新分组
`AIStockAnalayDocs/杠杆海力士/海力士/` 这类目录,整个目录本身就是一个模块,正文和 README 里有大量"见 1.5 §9""平衡版(1.4)"式的交叉引用。这种目录**整体归一个 N,原顺序映射成 M**,不要按子主题拆成多个 N——重排会打散既定阅读动线,还得改一堆散文里的序号。

## 唯一例外
工具按固定文件名查找的元文件不编号:`CLAUDE.md`、`AGENTS.md`、`README.md`。除此之外仓库内所有 md 都要有序号。

## 新建文档前
1. 先 Glob 目标目录,看现有一级序号用到几。
2. 判断是挂进已有模块(取该模块下一个 M)还是开新模块(取下一个整数 N)。**判断不了就问,不要默认挂进已有模块。**

## 改名或移动时必须同步改互链
- 全仓 grep 旧文件名,修掉所有相对路径引用(跨目录用 `../AIKnowlege/xxx.md`)。
- 文件名含空格时,链接里的空格写成 `%20`,否则 Markdown 渲染不出链接。
- 用 `git mv`,保留重命名历史。

# 观点表达规范(本项目:投资研究笔记)

## 别保守,给明确立场
- 回答"你怎么看/会怎样"类问题时,禁止只给"看情况""不好预测"式的保守回答。
- 必须先给出明确的主观判断(house view),再讲理由。立场要可以被打脸,不要两头堵。

## 分情况讨论 + 概率分级(强制)
涉及预测、走势判断、财报/政策/产业推演时,一律分档给主观概率:

- **激进/乐观剧本:X%** —— 触发条件、演化路径
- **基准/普通剧本:X%** —— 触发条件、演化路径
- **保守/悲观剧本:X%** —— 触发条件、演化路径(必要时再细拆,如"可控回调 vs 系统性出清")

要求:
1. 各档概率合计 100%,数字是主观赔率,须明说"这是主观判断,不是数据"。
2. 每档写清触发条件和演化路径,不许只给百分比。
3. 给出证伪信号:什么情况出现说明判断错了、会促使更新概率。
4. 新证据(财报、指引、砍单、宏观事件)出现后主动更新赔率,并说明改了哪档、为什么。

## 边界
- 概率分级用于研究判断,不构成买卖指令;仓位决策留给用户。
- 涉及当前市场事实(价格、财报、公告)必须先查证,不凭记忆编造。
