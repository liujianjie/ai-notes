# Kimi K3 开源：部署成本与硬件受益方

> 2026-07-28 与 Claude 的讨论整理。承接 [2.4 国产开源模型打平后的私有化浪潮](2.4%20国产开源模型打平后的私有化浪潮四市场受益环节与ETF.md) 和 [2.5 国产模型私有化部署产业链卡点与ETF](2.5%20国产模型私有化部署产业链卡点与ETF（A股美股韩股日股）.md)。那两篇的起点是一句假设："如果国产开源模型能和美国主流打平，企业就自己部署。" 2026-07-27 月之暗面开源 Kimi K3，这个假设的前半句兑现了。本篇算清后半句的账：到底要多少硬件、多少钱，以及这笔钱流向谁。硬件价格是我的估算不是实时报价，概率是主观赔率不是数据，不构成投资建议。

## 一、事实基线

7 月 16 日 K3 上 API，7 月 27 日"开放日"放出权重、技术报告和三个训练基础设施。

| 项目 | 数值 |
|---|---|
| 总参数 / 每 token 激活 | 2.8T / 104B |
| 专家数 | 896 个，每 token 选 16 + 2 个共享 |
| 层数 | 93（69 层 KDA + 24 层 Gated MLA）|
| 量化 | MXFP4 权重、MXFP8 激活，QAT 训出来的 |
| 上下文 | 1,048,576 tokens |
| 官方推荐引擎 | vLLM、SGLang、TokenSpeed |
| 许可 | Kimi K3 License（仓库内 LICENSE 文件为准）|

仓库：

- 主模型 [MoonshotAI/Kimi-K3](https://github.com/MoonshotAI/Kimi-K3)，技术报告 `k3_tech_report.pdf` 在仓库里，权重在 HuggingFace `moonshotai` 组织下
- [MoonshotAI/MoonEP](https://github.com/MoonshotAI/MoonEP)，动态冗余专家的 EP 通信库
- [MoonshotAI/FlashKDA](https://github.com/MoonshotAI/FlashKDA)，KDA 的 CUDA kernel
- [kvcache-ai/AgentENV](https://github.com/kvcache-ai/AgentENV)，Agent 沙箱，MIT 许可，注意在 kvcache-ai 组织下不在 MoonshotAI 下

严格说开源的是**权重 + infra 代码**，训练全流程源码没给。这和 Llama、DeepSeek 的口径一致。

## 二、卡的是显存容量，不是算力

三条硬事实，决定了后面所有的钱怎么算。

**MXFP4 是原生格式**。不是事后压的，是量化感知训练直接训出来的。所以权重占用是 2.8T × 0.5 byte ≈ **1.4 TB**，不是 BF16 的 5.6TB。网上流传的"BF16 权重 594GB"是错的，那个数字对不上任何一种精度。

**每 token 只激活 104B**。单 token 的计算量大致等同一个 104B 稠密模型，算力需求并不夸张。但 MoE 不省显存，896 个专家全都得常驻，你不知道下一个 token 会路由到哪。**算力可以省，显存一分不能省**，这是 MoE 部署最反直觉的地方。

**93 层里 69 层是线性注意力**。KDA 是月之暗面自研的混合线性注意力，加上剩下 24 层用 Gated MLA（本身就是压缩过的），1M 上下文的 KV cache 比同规模全注意力模型小一大截。这条其实削弱了"长上下文推动 HBM 需求"的叙事，真正撑起需求的是权重本身那 1.4TB。

按 1.4TB 除单卡显存，最低配置：

| 卡 | 单卡显存 | 装下权重最少几张 | 备注 |
|---|---|---|---|
| MI355X | 288GB | 5 张 | 8 张有 2.3TB，余量最舒服，且原生 FP4 |
| B200 | 192GB | 8 张 | 单节点刚够，KV 和激活只剩 136GB，小 batch |
| H200 | 141GB | 11 张 | **8 卡单节点装不下**，很多教程算错了 |
| H100 | 80GB | 18 张 | 无原生 FP4，要软件反量化 |
| H20 | 96GB | 15 张 | FlashKDA 的官方 benchmark 就跑在这上面 |

Moonshot 官方推荐 64 卡以上的超节点。那不是为了装下，是为了 EP 并行的通信效率和吞吐——MoonEP 这个库存在的全部意义，就是解决 896 个专家在负载不均时的通信塌方。

## 三、自建的打平点在哪

租 32 张 B200 跑一个月（$8/卡·小时估）：32 × 8 × 730 ≈ **18.7 万美元/月**。

官方 API 是 $3/M 输入（cache miss）、$0.3/M 缓存命中、$15/M 输出。按输入输出 10:1 估，混合约 $4.1/M token。

18.7 万美元能从 API 买约 457 亿 token，折合**日均 15 亿 token**。低于这个量，自建不如买 API。

但真正要命的是下一步。32 张 B200 满打满算的吞吐大概就在日均十几亿 token 这个量级，也就是说**打平点约等于"集群 7×24 跑满"**。企业实际利用率能有三到五成就不错了，算上闲置，永远打不平。

所以结论比 2.4 那篇激进的说法要收敛：**K3 这个级别的模型，绝大多数企业私有化在经济上不成立**。自建只在三种情况下有理由——数据主权是硬合规要求（金融、政务、军工）、已经有闲置 GPU 集群、或者用量真的大到工业级。

## 四、对 2.4 私有化论点的修正

2.4 的四个判断，现在可以逐条打分：

1. "模型本身不是利润池，钱流向硬件和集成" —— **成立且被强化**。K3 免费，API 只卖 $3/$15，模型层利润被自己人打没了。
2. "私有化 = 推理需求，不要万卡光互连" —— **这条要改**。K3 推荐 64 卡以上超节点，896 专家做 EP 的通信量不小，虽然还够不上万卡训练集群，但也远不是 2.4 里设想的"企业几台服务器"。scale-up 互联（NVLink 域、铜背板）在这个场景里是必需品，不是可选项。
3. "中国企业私有化 ≈ 国产化" —— **成立**。FlashKDA 的 benchmark 跑在 H20 上，说明月之暗面主力算力就在受限卡和国产卡上，国产链的适配路径是通的。
4. "GPU 租赁云是私有化的对手盘" —— **反了**。K3 的门槛高到大部分企业只能租，neocloud 反而吃到"想用开源前沿模型又不想自建"的那批需求。

一句话：开源把**模型能力**平民化了，但没把**部署能力**平民化。2.4 设想的"各家上规模的企业都自己部署"这一波，在 K3 这个参数量级上不会发生；会发生的是集中到少数几家托管方手里。

## 五、利好排序

按确定性从高到低：

**HBM**。2.8T 参数原生 4bit 还要 1.4TB，这是把显存容量变成一等约束的典型负载。而且开源意味着几百家机构各自部署一份，需求是复制的不是共享的。海力士、三星、美光。这条和 [1.7 AI产业对HBM依赖度分析](../AIStockAnalayDocs/杠杆海力士/海力士/1.7%20AI产业对HBM依赖度分析.md) 的框架一致，K3 只是新增了一个量化过的例证。

**原生 FP4 硬件（Blackwell 及以后）**。这是代际分水岭。B200/GB200/B300 的 Transformer Engine 原生吃 FP4，Hopper 不吃，同样跑 K3 前者满血后者要在 kernel 里反量化。开源模型集体转向原生低精度训练，会加速 H100/H200 存量卡的贬值——这对二手 GPU 市场和折旧假设是个负面因子，值得单独盯。

**Scale-up 互联与超节点**。64 卡起、896 专家做 EP，必须在一个高带宽域里。GB200 NVL72 这种 rack-scale 是为这个场景生的，连带铜缆背板、交换芯片。华为 CloudMatrix 384 的超节点思路在这个模型上被验证是对的方向。注意这条修正了 2.4 里"光模块和本主题无关"的结论：rack 内是铜不是光，所以受益的是铜连接和 scale-up 交换，光模块确实还是不沾边。

**AMD MI355X**。288GB 显存加原生 FP4，8 卡 2.3TB 余量充足，vLLM 和 SGLang 对 ROCm 的支持这两年补上来了。开源模型不挑供应商，这是 AMD 少数能正面竞争的场景，被市场低估。

**国产链**。昇腾 910C、寒武纪思元这类大显存卡加超节点方案有实打实的场景。弹性最大，但适配进度、良率、产能三重不确定，仓位上别当主力。

## 六、概率分级

**以下是主观赔率，不是数据。** 判断对象：K3 开源在未来 3–6 个月对硬件链条的影响。

**乐观 30%**。开源模型部署需求形成真实增量，托管方（云厂商、主权 AI 集成商）大规模上架 K3 级模型，HBM 和 rack-scale 服务器订单在 2026H2 明显超预期。触发条件是三家以上主流云厂商把 K3 做成一级托管服务并披露容量投入，同时 HBM 现货价格上行。

**基准 50%**。需求主要走 API 和云托管，自建停留在少数金融、政务、大厂。硬件受益体现在叙事和估值，不在当期订单，跟着整体 AI capex 走，K3 只是加了把火。这是我的主判断，理由就是第三节那个"打平点等于集群跑满"的账——门槛实在太高。

**悲观 20%**。开源反过来压推理定价。K3 把前沿能力打到 $3/$15，闭源同档位的定价权受冲击，推理毛利被挤，云厂商重算 ROI 后放缓 capex。7 月 27 日纳指跌约 1%、Intel 和英伟达被抛，市场的第一反应就是这一档。

## 七、证伪信号

- **两周内 HuggingFace 上 K3 的社区量化变体数量**。如果到 8 月中旬还没出现大量 GGUF/AWQ/更激进的低比特版本，说明 1.4TB 的门槛确实劝退了社区，往悲观档偏。反之如果出现能塞进 4 卡的可用蒸馏版，乐观档概率上调。
- **英伟达下季财报里 rack-scale（GB200/GB300）营收占比**。加速则支持第三条"超节点"判断。
- **海力士、美光的 HBM 出货指引**。上调是乐观档的直接证据。
- **有没有非 AI 原生的大型企业公开宣布自建 K3**。出现三家以上，说明我第三节"经济上不成立"的算账错了，得推翻重来。
- **月之暗面自己的 API 定价**。如果三个月内降价，说明推理成本比我估的低，打平点要下修。
